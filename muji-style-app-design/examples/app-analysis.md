# Example Analysis

## Case Study: MUJI Application


## Observation

The application contains only a few primary navigation items.

Most secondary functions are hidden.


## Design Reasoning


### Navigation

The bottom navigation focuses on:

- high-frequency tasks
- user goals


The number of tabs avoids cognitive overload.


---

## Launch Behavior


Interesting pattern:

The application opens directly into the membership/passport area.

Although it is the last navigation item.


Reason:

The system considers:

- access frequency
- user expectation
- interaction duration


Users check points frequently,
but stay briefly.


Therefore:

Launch state and navigation order are separated.


---

## Design Lesson


Do not assume:

First tab = most important.


Instead analyze:

- frequency
- urgency
- user motivation
